## The build blocker (resolved)

- **Was:** `src/world/address/AddressDesk.tsx:32` imported `./hold.server`, and
  TanStack import-protection rejects `**/*.server.*` from the client bundle, so
  `vite build` failed on every branch and main.
- **Now:** `AddressDesk.tsx:6` imports `./addressHolds` (a client-safe module of
  `createServerFn` wrappers); the DB access stays server-side inside those fns.
  `grep -rn "hold.server" src/` finds nothing. `vite build` on main: **exit 0**
  (verified twice — /tmp/build-main.log, /tmp/build-w3.log).
- `fix/addressdesk-serverfn` is indeed moot: main already contains the fix.

## Security scan

- **Env leaks:** `process.env` in server-only modules reads keys server-side
  (`neura.server.ts:64,205` — `NEURA_WEBHOOK_SECRET` etc. via `lightningKey`/
  HMAC verify); none are interpolated into client bundles. No `VITE_`-prefixed
  secret in the tree. No `import.meta.env` secret leakage found.
- **Client/server boundary:** all server fns go through `createServerFn` +
  `authMiddleware`; the reception proxy keeps office credentials server-side
  (see the reception audit). The `.server` suffix convention is respected.
- **No new attack surface** from the merges: the feature audits cover the
  security-relevant additions (inspect's Overpass id validation is the one
  outstanding item, in its audit).
